غالباً بتستخدمه من غير ما تاخد بالك محتاج فهم أعمق لسه هتتعلمه
DI (constructor + Provider)، Observer (Streams/Cubit)، Facade، Singleton، Simple Factory، MVVM-style Cubits، Data Mapper Repository (بالـ interface)، Strategy، Adapter، Command، Service Locator vs DI Clean Architecture، Result type، Decorator (class-level)، State (GoF)، Builder، Abstract Factory، Factory Method، Prototype

أهم فجوة عند أغلب Flutter developers: Abstraction (interfaces) + Dependency Inversion. ده اللي هيفتحلك Repository الصح و Clean Architecture و Decorator و Unit Testing للـ Cubits. ابدأ بيه.

المرحلة 1 — الأساسيات (أسبوع–أسبوعين)

# المفهوم ليه دلوقتي تمرين

1.3 Composition over inheritance Decorator و Strategy مبنيين عليها —
1.4 Unit testing بـ fakes من غير tests مش هتحس بقيمة DI اكتب test لـ AttendanceService (مثال 04) بـ FixedClock

المرحلة 2 — الأنماط الأكثر استخداماً في Flutter (3–4 أسابيع)

2.1 Repository (بالشكل الكامل) — High

  • يستاهل؟ أيوه جداً. أكتر pattern بيتسأل عنه في Flutter interviews.
  • ليه مهم: بيفصل "منين البيانات" عن "هعمل بيها إيه".
  • هتحتاجه فين: أي feature فيها API + cache + offline (Attendance، Employee Profile).
  • قبله: Interfaces (1.1)، DI.
  • بعده: Data Source، Clean Architecture، Result type.
  • تمرين صغير: مثال 03_repository_employee_profile.dart: زوّد LocalDataSource (cache بـ SharedPreferences) وخلي الـ repository يقرا local الأول.
  • Feature حقيقية: في مشروعك أو مشروع تجريبي: AttendanceRepository (interface) + RemoteAttendanceDataSource + LocalAttendanceDataSource.
  • الصعوبة: متوسطة · الأولوية: High

2.2 Result type / Error handling as values — High

  • يستاهل؟ أيوه. Flutter نفسه بيوصي بيه في الـ architecture docs.
  • ليه مهم: لما الـ services بترمي exceptions، كل Cubit لازم يفتكر try/catch. الـ Result بيخلي الـ compiler يجبرك.
  • قبله: sealed classes، pattern matching في Dart 3.
  • بعده: Command (Flutter docs بيربطهم ببعض).
  • تمرين: مثال 14_result_error_handling.dart: زوّد NetworkFailure و PermissionFailure كـ sealed subclasses.
  • Feature: LoginRepository.signIn() يرجّع Result<User>.
  • الصعوبة: سهلة-متوسطة · الأولوية: High
  • مصدر: Flutter – Result pattern

2.3 DI vs Service Locator (فهم عميق) — High

  • يستاهل؟ أيوه. أغلب Flutter apps بتستخدم الاتنين، ولازم تعرف تشرح الفرق.
  • تمرين: مثال 05. بعدين جرّب get_it في مشروع صغير وقارن بـ Provider.
  • الصعوبة: سهلة · الأولوية: High
  • مصدر: Fowler – Injection

2.4 Strategy (بالـ interface مش بس function) — Medium-High

  • ليه مهم: طرق check-in مختلفة، طرق دفع، sorting/filtering، تسعير.
  • قبله: Interfaces.
  • بعده: State (شبهه في الشكل).
  • تمرين: مثال 07: زوّد FaceIdCheckIn من غير ما تعدل أي class قديم.
  • Feature: إعداد الشركة بيحدد طريقة الـ check-in.
  • الصعوبة: سهلة · الأولوية: Medium-High

2.5 Adapter — Medium

  • ليه مهم: لو هتربط HR app بـ Odoo أو API قديم، ده بالظبط اللي هتعمله.
  • تمرين: مثال 08: اعمل adapter تاني لـ API بيرجع الرصيد بالدقايق.
  • الصعوبة: سهلة · الأولوية: Medium

المرحلة 3 — أنماط متقدمة (3–4 أسابيع)

Pattern يستاهل؟ فين في Flutter قبله تمرين صعوبة أولوية
Decorator أيوه caching/logging/retry حوالين repository Interfaces، Repository مثال 10: زوّد RetryStatsRepository متوسطة Medium
Command أيوه (Flutter docs بيستخدمه مع ViewModels) أزرار بـ loading/error state، offline queue، undo Result مثال 11 + اقرا Flutter Command docs متوسطة Medium
State (GoF) ساعات workflows: leave request، approval chains، order status sealed classes، Strategy مثال 12: زوّد Cancelled بعد Approved بشرط قبل تاريخ البداية متوسطة Medium-Low
Builder قليل في Dart requests/reports/queries معقدة named params مثال 13: زوّد includeWeekends() و validation سهلة Low
Factory Method (GoF) للفهم platform-specific widgets (Cupertino/Material) Inheritance، Factory اعمل abstract class Dialog { Widget createButton(); } بـ 2 subclasses متوسطة Low
Abstract Factory للـ interviews بس غالباً theme/platform families Factory Method UiFactory بيعمل Button + Switch لـ iOS و Android متوسطة-صعبة Low
Prototype للفهم نادر. copyWith بيغطي الحاجة — اكتب فقرة: ليه copyWith مش Prototype سهلة Low

المرحلة 4 — Architecture و Scalability و Maintainability (4–6 أسابيع)

4.1 MVVM بالشكل الرسمي في Flutter — High

  • اقرا Flutter App Architecture Guide و الـ case study.
  • قارن بمشروعك: Cubit = ViewModel ✓. بس شيل TextEditingController من الـ state، والـ StreamBuilder اللي بيقروا Firestore من الـ UI (جرّب على مشروع تدريبي الأول).

4.2 Clean Architecture — High (للـ interviews) / Medium (للتطبيق)

  • قبله: Repository + interfaces + Result + DI.
  • المفاهيم: Entities، Use Cases، Repository interfaces في الـ domain، implementations في الـ data، Dependency Rule (الـ dependencies بتشاور للداخل).
  • تمرين: feature واحدة كاملة (Attendance check-in) بـ 3 layers: domain/ (entity + repo interface + CheckInUseCase)، data/ (data sources + repo impl)، presentation/ (cubit + screen).
  • امتى زيادة؟ app صغير أو MVP سريع. الـ use case اللي بيعمل return repo.x() بس = boilerplate.
  • مصدر: Uncle Bob – Clean Architecture

4.3 Modularization و Dependency direction — Medium

  • علامات المشكلة: package cycle بين packages المشروع، أو core/ بيستورد من features/.
  • تمرين (على ورق): ارسم الـ packages والأسهم. حدد إزاي تطلع shared_models package يكسر الـ cycle.

4.4 Testing strategy — High

  • Unit (cubits بـ fake repositories)، widget tests، integration.
  • قبله: كل المرحلة 2.
